What this page is showing

Two layers decide. The structural layer (in the page) catches a rate or a port sweep, which are shapes over time and have no payload to read. The content layer is the repo's real guard, over the arm you pick, catching PII and credentials. Each row names the tier that fired.

A model is only asked when there is something to decide. If no rule fired, the whole base response set is available and the flow is allowed deterministically. Narrow it and the ontology asks the arm which permitted response to use — the model chooses from the ontology's menu, never outside it.

Unchecked is not clean. When the content tier cannot answer, the flow is unverified, not safe: Allow is withdrawn and the flow is held at the guard. A production guard would fail closed here; this demo shows the failure rather than hiding it, so a blind spot is visible.

Destroying traffic is escalation-only. A first offence is rate-limited. Only a source that has already had a flow blocked may be dropped or quarantined — that is an axiom, not a preference.
